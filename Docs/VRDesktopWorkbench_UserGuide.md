# VR 桌面调试工作台使用说明

## 用途与当前状态

供没有连接头显的同学在 Unity 编辑器里检查视角、交互、界面和场景流程。当前版本在 Mac / Unity 2022.3.62f3 上完成 Play Mode 验证。Windows 编辑器兼容路径已实现，但本轮未在 Windows 上实际运行；正式 Windows + SteamVR + Quest 验收仍不可省略。

工作台在独立 assets/tool 分支维护，基线为 interaction 的 2e13ea7。只有工具分支包含工作台和必要适配，不自动合并到其他分支。保留基线中的操作提示、开场环境音时长与入台证功能。

## 一、第一次启动

1. 在 Unity Hub 选择 Add / 添加，选择 VRDesktopWorkbench 工程文件夹，以 Unity 2022.3.62f3 打开。
2. 等待导入、编译完成。打开菜单 **XR Team > VR 桌面调试工作台**。
3. 在“控制台”的“启动场景”选择已保存的场景，例如 scene_01 或 scene_07。
4. 手动保存或撤销已有场景改动。工作台遇到未保存场景会拒绝启动，不会代你保存团队文件。
5. 点击“启动桌面模拟”，等待进入 Play Mode。
6. 点击 Unity 的 Game 标签，让 Game 视图获得焦点，才会读取键盘和鼠标移动输入。
7. 测试完成后点击工作台顶部“停止并恢复”，或停止 Unity Play Mode。

不要直接按 Unity Play 按钮期待模拟自动开启。未手动启用工作台时，项目仍走原有 SteamVR 流程。

### 旧工具处理

如果自己的工程中还有未上传的 `Assets/LocalOnly/CenserMacDebug.cs`，先将该旧脚本移到 Assets 之外备份。它引用已不存在的 DummyController，会导致当前团队工程编译失败。不要同时启用旧工具和工作台。

## 二、键盘和鼠标

| 操作 | 按键 |
|---|---|
| 摄像机前后左右移动 | W / A / S / D |
| 摄像机下降 / 上升 | Q / E |
| 转动视角 | 方向键，或按住鼠标右键移动 |
| 控制器前后左右移动 | I / J / K / L |
| 控制器下降 / 上升 | U / O |
| 控制器旋转 | 按住鼠标中键移动 |
| 控制器俯仰、偏航、翻滚 | 数字小键盘 8/2、4/6、1/3 |
| 模拟扳机按下、保持、释放 | 按住 / 松开 Space |
| 通用目标握持事件 | 按住 / 松开 F |
| 切换模拟左右手 | Tab |
| 手柄回到摄像机前方 | R |
| 摄像机和手柄复位 | C |
| 关闭入台证预览 | Esc |

没有鼠标中键或数字小键盘时，可以在控制台实时输入“手柄旋转”的欧拉角。先开启控制台“模拟扳机保持”，再调整角度，也可检查证件的旋转。

工具面板里的扳机／握持保持按钮适合没有按键焦点时使用，再点一次即释放。它们是持续状态，不是单击一次自动松开的按钮。

## 三、六个页面

### 控制台

选择启动场景；调整摄像机和手柄移动、转向速度；设置默认眼高；开关简易摄像机碰撞、场景音频暂停和操作提示。运行时显示当前输入路由、命中物体、扳机状态和手柄位姿。

简易碰撞只帮助桌面查看，不代替真实玩家 CharacterController 验收。“冻结模拟输入”也不是暂停整个故事，音频和实时计时剧情可能继续。

### 场景与视角

列出 Build Settings 中的场景。“调试加载”会加载预先隔离的副本，并在日志中标记为人为跳过剧情；它不能作为自然剧情转场通过的证据。

个人书签记录当前场景、观察位置和方向，只能在同一场景恢复。书签与速度等设置存放在本机 EditorPrefs，不会写入共享场景，也不应提交。

### 对象检查

点击“刷新列表”，显示显式通用目标、入台证、语言选择、uGUI 按钮、高亮组件和博物馆剧情入口。运行时可点击“观察”“手柄靠近”“手柄瞄准”。这些按钮只改变模拟观察位置，不移动业务物体。

“检查场景”检查碰撞体、必要引用、Missing Script 和文字可能裁切的问题。文字裁切结果是警告，需要人看截图，不能自动断言字幕一定正确。

### 光效与语言

模拟运行时选择 SoftInteractionHighlight 组件，比较默认、靠近和持有隐藏状态，并调整颜色、宽度和强度。结束强制状态、换目标或关闭窗口会恢复记录的原参数。

“预览中文／英文”是直接设置调试语言，不是语言按钮射线验收。要验证按钮选择，应从 scene_01 开始，用模拟右手射线与 Space 扳机操作。

### 记录与验收

显示最近事件；运行核心自检和当前场景检查；保存人工备注；导出 JSON 报告。人工确认显示 MANUAL_PASS / MANUAL_FAIL，与自动断言 PASS / FAIL 分开；Quest 验证显示 NOT_TESTED。

事件列表最多保留1500条，界面显示最近100条。工具跨脚本域重载时内存记录会重置；重要记录请在停止 Play Mode 或重新编译前导出。

顶部“截图”导出模拟摄像机图像，不包含编辑器工具窗口。请保存到仓库外；报告和截图可能包含本地路径，分享前检查内容。

### 帮助

内置快捷键与支持边界，供同学不打开文档时查阅。

## 四、团队交互测试

### 语言选择

从 scene_01 启动。右手白色射线始终显示，未命中时5米；瞄准按钮后变绿。按 Space 选择中文或英文。使用与真实右手 GrabPinch 相同的语言选择处理函数。

### 香炉

保留真实剧情的等待条件。需要旁白流程到达“等待交互”阶段，再把模拟右手靠近香炉并按 Space。调用真实 Interact 方法，不直接加载下一场景。确认进入记忆的按钮也可用射线操作。

### 入台证

从 scene_07 启动后，等待约3秒开放自由探索。右手瞄准入台证，按 Space 进入悬浮查看；瞄准证件预览区域，按住 Space 同时旋转模拟手柄。瞄准“展开／合拢”或“放回桌面”并按 Space 操作。新按钮文字跟随全局语言。

左手不会操作团队约定的右手专用语言、记忆确认和证件界面；左手可测试允许左手的通用目标。

## 五、让新物体接入

1. 在原始编辑场景选中目标，通过“对象检查”中的“添加通用适配器”按钮添加 DebugInteractionTarget；支持 Undo 撤销。
2. 在 Inspector 中指定本体或子节点的有效 Collider，配置接近距离和允许的左右手。
3. 将 onSelect、onNearby、onFar、onHeld、onReleased 等事件连接到真实业务方法。未连接时工作台会提示，不会猜测物体应做什么。
4. 若需要高亮，可将接近／远离事件连接到 SetNearby(bool)，握持／释放事件连接到 SetHeld(bool)，在事件参数中设置 true/false。
5. 保存场景并启动模拟；用 Space 测选择，用 F 测握持事件。

这一步会实际修改你选中的原始场景，应该单独审查和提交。新物体不是因为添加适配器就自动获得 SteamVR 真实抓取，也不会自动移动或跟随手柄；业务系统仍需接入相同方法。

世界空间 uGUI 需要启用的 Canvas、GraphicRaycaster 和可射线检测的 Graphic。支持常规按钮点击；任意第三方 VR UI、UI Toolkit、屏幕空间UI和复杂拖拽控件不保证兼容。

## 六、安全、恢复与故障

- 工作台为已启用构建场景和启动场景生成本地副本，停用副本中的原生 SteamVR 硬件组件；不保存这些状态到原场景。
- XR自动启动仅在模拟会话中临时停用并恢复。项目 XR 配置文件不应出现提交改动。
- 正常停止后恢复原编辑场景并清理本次生成目录；异常退出后点击控制台“恢复原场景”。
- Generated 目录和它的 .meta 被 .gitignore 排除；不要上传 Library、Logs、UserSettings、验证导出目录或截图。
- 若导入期间出现原项目 OpenVR 包中的 immutable folder / .meta 诊断，或 Assets/Subtitles.meta 无效GUID，这是已有资源问题，应单独处理；本工具不修改第三方包来掩盖诊断。
- 若没有移动：先点击 Game 视图，检查是否冻结输入。若没有命中：切回右手、使用“瞄准”辅助，再检查物体的碰撞体和剧情条件。
- Windows 编辑器模拟、正式 Windows 构建和 Quest 实机仍需团队补充验收；本工具不声称验证真实追踪、原生控制器绑定、双眼图像和头显性能。
